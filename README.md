# NicoGura 公式Webサイト

FiveM RPサーバー「NicoGura / にこぐら」の公式Web入口と、検索・共有しやすいルールサイトです。HTML・CSS・JavaScriptだけで動く静的サイトで、追加ライブラリや有料サーバーは不要です。

- 公開URL: <https://mochidukiakiya.github.io/nicogura-rules/>
- 専用リポジトリ: <https://github.com/mochidukiakiya/nicogura-rules>
- ページ: HOME / RULES / CHANGELOG / 404 / ローカル編集画面
- データ: `data/rules.json`

## 現在の掲載状態

2026-10-04時点は**準備版**です。正式公開ルールは0件、仮カテゴリーは18件です。18枚のカードは掲載準備の案内であり、施行されたルールではありません。

確認できた運営資料には断片的なメモがありましたが、正式な本文、定義、例外、施行日、運営承認を確認できなかったため、公式ルールとして採用していません。参考サイトの文章も使用していません。本文は運営が確認・承認した内容から追加してください。掲載状況の引き継ぎは `docs/CONTENT_STATUS.md` に記載しています。

## 最初にローカルで確認する

1. Node.js 20以上を用意します。
2. このリポジトリのフォルダーでターミナルを開きます。
3. 次のコマンドを実行します。インストール作業は不要です。

```sh
node scripts/serve.mjs
```

ブラウザで <http://127.0.0.1:4173/> を開きます。停止はターミナルで `Ctrl + C` です。ポートを変える場合は `node scripts/serve.mjs 4174` のように指定できます。

HTMLファイルのダブルクリックではデータ読み込みが制限される場合があるため、ローカルサーバーで確認してください。このサーバーは自分のPC内でのみ待ち受け、公開用ファイルだけを配信します。

## おすすめ：ブラウザで文章を編集する

ローカル確認中に <http://127.0.0.1:4173/editor/> を開くと、現在のJSONが読み込まれます。公開サイトの `/editor/` でも利用できます。必要なら「JSONを読み込む」からPCに保存した `rules.json` を選択してください。

1. 左のルール一覧から編集したいカードを選びます。
2. タイトル、カテゴリー、要約、本文、タグ、重要度、更新日などを変更します。
3. 「このルールの変更を適用」を押します。
4. サイト設定のバージョン・更新日も変更して「サイト設定を適用」を押します。
5. 必要なら「更新履歴を追加」で変更内容を記録します。
6. 「rules.jsonをダウンロード」を押します。JSONの構造や危険な文字列に問題がある場合は、内容を直すまでダウンロードできません。
7. ダウンロードしたJSONの内容を運営内で確認します。
8. GitHubのこのリポジトリで `data/rules.json` を開き、ファイルを置き換えてCommitします。

**編集画面は認証やサーバー保存の機能を持ちません。** 編集内容はそのタブ内にだけ保持され、ファイルのダウンロードまでPCにも保存されません。他の人が編集画面を開いても、サイトを上書きすることはできません。ダウンロードしたファイルをGitHubへCommitしたときに初めて公開更新が始まります。

本文が段落だけなら、空行で段落を分けて入力できます。見出し・箇条書き・注記を含む既存本文は「高度な編集（本文ブロックのJSON）」で開かれ、その構造を維持します。本文ブロックにHTMLは使用できません。表示側も文字列をテキストとして扱います。

編集中のルールを切り替えるとき、未適用の変更がある場合は破棄するか確認が出ます。削除にも確認が出ます。タブを閉じる前に、必ずダウンロードしてください。

## GitHubで公開データを置き換える

GitHubの `data/rules.json` を開いて鉛筆アイコンの編集操作を使い、ダウンロードしたJSON全体を貼り付けてCommitします。GitHubのアップロード機能を使う場合は `data` フォルダー内に同じ名前の `rules.json` をアップロードしてください。

Commit後、`Actions` の「Publish NicoGura website」が実行されます。チェックと公開が成功すると、通常は数分でサイトが更新されます。所要時間はGitHubの混雑状況により変わります。新しい内容が見えない場合は、Actionsの結果を確認してからブラウザを再読み込みしてください。

失敗した場合は、Actionsの `Validate public content` を開くと、重複したID・無効な日付・存在しないカテゴリー等のエラーが表示されます。公開前に自分のPCでも次のコマンドで確認できます。

```sh
npm run validate
```

このチェックはJSON構造、ID・番号の重複、カテゴリー参照、日付、リンク、画像の存在、公開ファイルの種類、認証情報や内部IPらしい文字列を確認します。ルール本文の正しさや運営承認は人が確認してください。

## rules.jsonを直接編集する場合

ファイル全体の構成は次の通りです。

| 項目 | 用途 |
| --- | --- |
| `site` | サイト名、説明、バージョン、更新日、お知らせ、公式リンク、画像 |
| `categories` | カテゴリー名、短い表示名、説明、グループ |
| `rules` | 各ルールの本文・検索用語・表示設定 |
| `changelog` | 住民向けの更新履歴 |
| `settings` | 最近の更新バッジの表示期間、上部のクイックリンク |

JSONは文字列を半角の `"` で囲み、項目間を半角の `,` で区切ります。最後の項目の後ろにはカンマを付けません。編集に不慣れな場合はブラウザ編集画面を使ってください。

### ルールの追加と変更

編集画面の「＋追加」で、新しい準備中のカードを作れます。正式公開には運営承認済みの本文を入力して、`status` を `published` に変更します。JSONを直接編集する場合の形は次の通りです。これはデータ形式の例であり、公式ルールの内容ではありません。

```json
{
  "id": "your-rule-id",
  "number": 19,
  "title": "運営承認済みのタイトルを入力",
  "category": "basic",
  "tags": ["検索用のタグ"],
  "keywords": ["別の呼び方", "読み仮名"],
  "importance": "normal",
  "summary": "運営承認済みの要約を入力",
  "content": [
    { "type": "paragraph", "text": "運営承認済みの本文を入力" },
    { "type": "heading", "text": "見出し" },
    { "type": "list", "items": ["項目1", "項目2"] },
    { "type": "note", "text": "補足説明" }
  ],
  "updatedAt": "2026-10-04",
  "new": true,
  "featured": false,
  "status": "pending"
}
```

- `id`: 英小文字で始まる英数字とハイフン。他のカードと重複させません。公開後に変更すると、住民が共有したURLが変わるため、可能な限り維持してください。
- `number`: 重複しない整数。正式公開時は1以上。新規の準備中カードでは0を使えます。
- `category`: `categories` 内にある `id` を指定します。
- `tags` / `keywords`: 検索対象になります。配列が不要な場合は `[]` にします。
- `status`: `pending` は「運営確認中」。`published` は運営承認後の正式公開です。
- `content`: 文章は `paragraph`、見出しは `heading`、箇条書きは `list` と `items`、注記は `note` で表します。

### カテゴリーを追加・変更する

編集画面の「カテゴリーを追加」で、ID・表示名・短い表示名・グループ・説明を入力します。直接編集する場合は `categories` 配列に次の形で追加してください。

```json
{ "id": "your-category", "label": "カテゴリー名", "shortLabel": "短い名前", "description": "説明", "group": "グループ名" }
```

表示名は変更できます。既存カテゴリーのIDを変更する場合は、そのカテゴリーを使用しているすべてのルールの `category` も変更します。ルールが参照しているカテゴリーを削除するとチェックに失敗します。18カテゴリーは現在の仮構成なので、正式データに合わせて整理してください。

### 重要度・NEW・更新日の変更

| `importance` | 表示 |
| --- | --- |
| `normal` | 通常 |
| `important` | 重要 |
| `prohibited` | 禁止 |
| `warning` | 注意 |
| `supplement` | 補足 |
| `exception` | 例外 |

追加したルールは `new: true` にし、`updatedAt` を更新します。既存ルールの変更時は `new: false` と更新日を指定します。正式公開済みのルールだけ、`settings.newBadgeDays` の期間内にNEWまたはUPDATEDバッジを表示します。期間は0〜365日、初期値は30日です。日本時間で更新日から期間を数え、未来の日付や期間外のバッジは表示しません。準備中のカードにも表示しません。

サイト全体の `site.updatedAt` と `site.version` も更新してください。日付は `YYYY-MM-DD` 形式です。正式ルールが未承認の間は「準備版」の表記を維持してください。

### よく見られるルールを指定する

各ルールの `featured` を `true` にすると、上部のクイックリンクに掲載できます。`settings.featuredRuleIds` にルールIDを並べることもできます。存在するルールIDだけを指定してください。閲覧回数を収集する機能はありません。

### 更新履歴を追加する

編集画面の「更新履歴を追加」で、日付、種別、タイトル、1行ごとの変更内容を入力します。直接編集する場合は `changelog` の先頭に追加してください。

```json
{
  "date": "2026-10-04",
  "type": "変更",
  "title": "変更内容のタイトル",
  "items": ["変更した点を住民に分かる言葉で記載"]
}
```

種別は `追加`、`変更`、`削除`、`お知らせ` を使えます。新しい履歴を上に置くと、住民が最新情報を見つけやすくなります。

### Discord・Xなどのリンクを設定する

`site.links.discord`、`x`、`fivem`、`official` に運営確認済みの `https://` URLを指定します。未確定の項目は `""` のままにしてください。空欄のリンクはサイトに表示されません。推測の招待リンクや接続先を設定しないでください。IPアドレス、認証情報、ローカルURLは許可しません。

### 画像を変更する

画像は `assets` フォルダーに置き、`site.assets` を変更します。

| 項目 | 用途 | 現在のファイル |
| --- | --- | --- |
| `logo` | サイトロゴ | `assets/logo.webp` |
| `header` | ヒーローの背景 | `assets/city.webp` |
| `icon` | ブランドアイコン | `assets/icon.webp` |

WebPなどの軽い形式をおすすめします。透明背景の白いロゴは濃い背景向けです。`assets/favicon.png` と `assets/apple-touch-icon.png` はブラウザやスマートフォンのアイコン用です。

DiscordやXの共有画像は `assets/og.png` です。変更時は、この画像を置き換え、各ページの `<head>` にある `og:image` と `twitter:image` も確認してください。共有用画像は1200×630pxを目安に、名称が小さい画面でも読める配置にします。タイトル・説明・canonical URL等のSEO設定は各ページのHTMLで変更します。デザインの色・余白・角丸は `assets/style.css` のCSS変数で管理しています。

## GitHub Pagesで無料公開する

GitHub Freeの公開リポジトリでGitHub Pagesを利用できます。料金と提供条件は[GitHubの公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)を確認してください。標準の `github.io` URLを使えば独自ドメインは不要です。

初回設定は次の通りです。

1. `nicogura-rules` というWeb専用の公開リポジトリを作成します。
2. このフォルダーのファイルだけを `main` ブランチへアップロードします。
3. リポジトリの `Settings` → `Pages` → `Build and deployment` の `Source` を **GitHub Actions** に設定します。
4. `Actions` の「Publish NicoGura website」を実行します。以後は `main` の更新で自動実行します。
5. Actionsが成功したら公開URLを開いて確認します。

`.github/workflows/pages.yml` は公開前チェックを行い、HOME、RULES、CHANGELOG、404、編集画面、画像・CSS・JavaScript、JSON、robots・sitemapだけを公開します。README、docs、開発スクリプト、ゲームファイルはサイトの公開成果物に含みません。

別のリポジトリ名や独自ドメインへ移転する場合は、各ページのcanonical・OGP URL、`robots.txt`、`sitemap.xml` と、`404.html` の `<base href="/nicogura-rules/">` を移転先に合わせて変更してください。ローカルサーバーはルート `/` と現在のプロジェクト接頭辞 `/nicogura-rules/` の両方を配信します。

このリポジトリはゲームサーバーのリポジトリから独立しています。ゲームの設定・認証情報・内部資料・個人情報を追加しないでください。

## サイト機能

全文検索はタイトル・本文・キーワード・カテゴリー・タグを対象にし、一致する語を強調します。カテゴリー変更はページ遷移なしで絞り込みます。各カードのリンクは `/rules/#ルールID` で共有でき、リンクコピーと「あとで見る」に対応しています。

保存したルールとテーマ選択は、そのブラウザのLocalStorageに保存されます。アカウント登録や閲覧情報の送信はありません。保存は他の端末と同期されません。初期テーマはOS設定に合わせ、ダーク・ライトを切り替えられます。

GUIDE、JOBS、CITY、FAQ、NEWS等は、運営承認済みの内容ができてからページを追加してください。現在、未作成のページへ誘導するリンクはありません。
